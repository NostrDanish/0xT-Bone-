# Security Audit — NostrDanish/0xT-Bone- — 2026-10-20

## Summary
Fork of 5ToddSmith5/T-Bone- (Kotlin Nostr client, upstream shipped as source ZIP v0.3.36; lineage daomah/bony → T-Bone → this fork, per FORK.md). Fork adds: side-by-side `social.tbone.fork` applicationId, a CI privacy gate (no-Google-services check on PRs/pushes), tag-based release workflow, a full React/Vite "T-Bone Web" PWA (NIP-07/nsec/NIP-46-Amber login, NWC zaps, encrypted private toolbox), and Amber remote-signer support. Custom changes are genuinely useful but introduce two real risks: plaintext key/wallet-secret storage in the web app, and a debug-key signing fallback in the release pipeline. No releases have been published yet, so neither has shipped to users. No committed secrets found.

Findings: 0 CRITICAL / 0 HIGH / 2 MEDIUM / 1 LOW

## Findings
| ID | Severity | File/Area | Issue | Recommended fix |
|----|----------|-----------|-------|-----------------|
| TB-01 | MEDIUM | src/lib/store.tsx (T-Bone Web) | Login secret key (`skHex` from nsec), the NIP-46 `clientSecretHex`, and the NWC connection URI (`settings.nwcUri` — a wallet-spending credential) are all persisted in plaintext `localStorage`. Any XSS or malicious browser extension = full identity + wallet theft. | Default to NIP-07/Amber (no local key); if local keys are kept, encrypt at rest with a user passphrase (the repo already has PBKDF2/AES-GCM code in the Private Toolbox — reuse it); never persist nwcUri secrets plaintext. |
| TB-02 | MEDIUM | .github/workflows/build-release.yml | If KEYSTORE_* secrets are absent, the release APK falls back to the publicly-known Android **debug key**. Updates signed with that key are forgeable by anyone; the fallback only prints a warning and still publishes. (Disclosed in release notes; no releases published yet.) | Make the release job FAIL when no release keystore is configured; never ship debug-signed release APKs. |
| TB-03 | LOW | upstream relationship | Upstream ships as a source ZIP, not git history — no commit-level provenance, no reliable freshness tracking; security fixes upstream are invisible until manually diffed. | Keep the documented manual diff process; consider vendoring upstream ZIPs as release artifacts for diffability; watch upstream releases. |
